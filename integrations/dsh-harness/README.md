# DSH Harness integration

Runs macchiatoBot as the agent backend of [DSH](https://github.com/Osc-7/macchiatoBot/…)
(a browser agent host), instead of mbot's own frontends.

This directory is a DSH **plugin pair**: a host-side module (the daemon client) and a
browser-side module (the UI). Both are installed into a DSH profile; macchiatoBot itself
needs no fork of DSH, only a small patch to the vendored agent loop that `vendor.mjs` applies.

```
integrations/dsh-harness/
├── lib/
│   ├── index.js            host plugin: agent loop bridge, workspace model, commands
│   ├── provider.js         exposes macchiatoBot as an LLM provider to DSH
│   ├── commands.js         /machine /workspace … chat commands
│   ├── client.js           browser plugin: terminal tab, workspace tab, layout, branding
│   ├── lab/
│   │   ├── wire.js         IPC transport (unix socket), stall detection with per-phase budgets
│   │   ├── turn.js         one DSH turn → one run_turn_stream; token deltas; watchdog
│   │   ├── step.js         one DSH step → one model call; streams deltas, appends tool events
│   │   ├── events.js       mbot event frames → DSH session events
│   │   ├── approval.js     mbot permission requests → DSH approval service
│   │   ├── job-watch.js    background jobs → wakes the session when they finish
│   │   ├── fs-ops.js       file channel (read/write/list) for remote workspaces
│   │   ├── remote-fs.js    /fs protocol client used by fs-ops
│   │   └── workspace-model.js  machines → projects → directories
│   ├── workspace-files.js  right-hand pane file browser
│   └── workspaces-sync.js  keeps DSH workspaces in sync with the daemon's
├── scripts/
│   ├── vendor.mjs          copy the running DSH's agent loop and apply the step() patch
│   ├── install.mjs         install this package into a DSH profile
│   ├── patch-dsh-web-url.mjs  pin the web token / public URL (see docs)
│   ├── smoke-*.mjs         offline self-checks (no daemon needed)
│   └── fake-daemon.mjs     a scripted daemon for the smoke tests
└── cordis.patch.yml        profile patch layer (trusted hosts, cookie age, bundle entry)
```

## How a turn flows

```
DSH turn
  └─ step()                       lib/lab/step.js
       └─ LabTurn                 lib/lab/turn.js
            └─ MbotLink  ──unix──> macchiato-automation
                 run_turn_stream {message, client_id, workspace}
                 ← assistant_delta / reasoning_delta / tool_call / tool_result / keepalive / final
       ├─ deltas      → AssistantStreamAttempt (live text, token accounting)
       ├─ tool events → session.append("tool/call" | "tool/result")   ← at real timestamps
       ├─ permission  → approval.request()  → resolve_permission
       └─ job_id      → job-watch polls job_status → agent.followup() wakes the session
```

## Install

```bash
# 1. a DSH profile to install into
dsh --profile lab --from-default-profile web

# 2. vendor the running DSH's agent loop (patches step()) and install this package
node scripts/vendor.mjs
node scripts/install.mjs lab

# 3. offline checks — none of them need a running daemon
npm run smoke:model && npm run smoke:fs && npm run smoke:stall \
  && npm run smoke:approval && npm run smoke:jobwatch

# 4. start
dsh --profile lab web
```

`install.mjs` deliberately uses `cp` rather than a package manager: the `@deepseek-ai/*`
imports must resolve to the *same instances* the running DSH uses, otherwise
`session.append()` and `AssistantStreamAttempt` no longer agree on their structures.

## Configuration

| Variable | Meaning | Default |
|---|---|---|
| `LAB_MBOT_ROOT` (or `MACCHIATO_HOME`) | macchiatoBot checkout, for the IPC socket | `$HOME/macchiatoBot` |
| `LAB_MBOT_SOCKET` | IPC socket path | `<root>/data/automation/automation.sock` |
| `LAB_MBOT_STALL_S` | how long the model may be silent before the turn is declared stalled | 600 |
| `LAB_MBOT_TOOL_TIMEOUT_S` | same, while a tool is running (heartbeats excluded) | 1800 |
| `LAB_MBOT_TURN_CAP_S` | hard per-turn ceiling | 1800 |
| `LAB_MBOT_VERBOSE` | dump the raw event stream to stderr | off |

The profile patch (`cordis.patch.yml`) also carries the DSH-side settings that matter:
`connection.trustedHosts` (behind a reverse proxy), `cookieMaxAgeDays`, and the bundle entry.

## Notes for reviewers

- `lib/upstream/` is **not** committed: it is generated by `scripts/vendor.mjs` from the DSH
  installation actually in use, and patched to call `labStep()` instead of the built-in step.
  Committing it would pin a third-party bundle and drift immediately.
- The browser module (`lib/client.js`) also carries the UI this deployment wanted: a terminal
  tab, a workspace tab, a progress chip, a mobile drawer, and the product brand. They are
  independent of the bridge — delete what you do not want, the adapter (`lib/lab/*`) keeps
  working.
- `docs/dsh-harness-bridge.md` documents the deployment side (token, trusted hosts, session
  TTL read from the checkpoint, per-phase timeouts) and the failure modes each piece addresses.
